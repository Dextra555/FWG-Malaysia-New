# StockLedgerReport Deep Analysis
## Purpose: Blueprint for creating Current Stock Report following the same pattern

---

## Summary

`StockLedgerReport.aspx` is a fully self-contained ASP.NET Web Forms page (no code-behind `.cs` file — all logic is inline `<script runat="server">`). It accepts query-string parameters from Angular, calls `sp_InventoryStockLedger` stored procedure (which reads from `VWStockLedger` view), and streams either a PDF (iTextSharp 5.5.x) or an Excel HTML-table response directly to the browser. The Angular component wraps the PDF in an `<iframe>` using `DomSanitizer.bypassSecurityTrustResourceUrl`.

The **Current Stock Report** will follow the exact same architecture:
- New ASPX page → calls `sp_CurrentStockReport` SP → reads `VWCurrentStock` view (or uses existing `GetStockBalanceSummary` repository logic) → streams PDF/Excel to browser
- New Angular component → same form pattern → iframe render

### 3. SQL: VWStockLedger View

**File:** `d:\Gunma\FWG-Malaysia-New\Database\17.StockLedgerReport_Migration.sql`

```sql
CREATE VIEW VWStockLedger AS
SELECT
    sl.ID, sl.TransactionNo, sl.TransactionDate, sl.TransactionType,
    CASE sl.TransactionType
        WHEN 'OPENING'      THEN 'Opening Stock'
        WHEN 'STOCK_IN'     THEN 'Stock In'
        WHEN 'ISSUE'        THEN 'Stock Issue'
        WHEN 'ISSUE_RETURN' THEN 'Issue Return'
        WHEN 'TRANSFER_IN'  THEN 'Transfer In'
        WHEN 'TRANSFER_OUT' THEN 'Transfer Out'
        WHEN 'ADJ_PLUS'     THEN 'Adjustment (In)'
        WHEN 'ADJ_MINUS'    THEN 'Adjustment (Out)'
        WHEN 'PURCHASE_RTN' THEN 'Purchase Return'
        WHEN 'DAMAGE_LOSS'  THEN 'Damage / Loss'
        ELSE sl.TransactionType
    END AS TransactionTypeLabel,
    sl.WarehouseID,  wh.Name AS WarehouseName,
    sl.ItemID,       im.Code AS ItemCode, im.Name AS ItemName,
    ic.Name AS CategoryName,  bm.Name AS BrandName,  um.Name AS UOMName,
    sl.InQty, sl.OutQty,
    SUM(sl.InQty - sl.OutQty) OVER (
        PARTITION BY sl.WarehouseID, sl.ItemID
        ORDER BY sl.TransactionDate ASC, sl.ID ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS RunningBalance,
    sl.UnitCost, sl.ReferenceType, sl.ReferenceID, sl.ReferenceNo, sl.Remarks,
    sl.LASTUPDATE, sl.LastUpdatedBy
FROM StockLedger sl
    INNER JOIN WarehouseMaster wh ON sl.WarehouseID = wh.ID
    INNER JOIN ItemMaster im      ON sl.ItemID = im.ID
    LEFT  JOIN InventoryCategory ic ON im.CategoryID = ic.ID
    LEFT  JOIN BrandMaster bm       ON im.BrandID = bm.ID
    LEFT  JOIN UOMMaster um         ON im.UOMID = um.ID;
```

Key design point: `RunningBalance` is calculated as a SQL window function partitioned by `(WarehouseID, ItemID)`, ordered by `TransactionDate, ID`. This mirrors the C# accumulator in `InventoryRepository.GetStockLedger()`.

### 4. SQL: sp_InventoryStockLedger Stored Procedure

**File:** `d:\Gunma\FWG-Malaysia-New\Database\17.StockLedgerReport_Migration.sql` (Section 3)

```sql
CREATE PROCEDURE sp_InventoryStockLedger
    @WarehouseID     INT          = 0,
    @ItemID          INT          = 0,
    @TransactionType NVARCHAR(50) = 'ALL',
    @FromDate        DATETIME     = NULL,
    @ToDate          DATETIME     = NULL
AS BEGIN
    SET NOCOUNT ON;
    -- ToDate extended to 23:59:59 (covers full day)
    SET @ToDate = DATEADD(SECOND, 86399, CAST(CAST(@ToDate AS DATE) AS DATETIME));

    SELECT v.ID, v.TransactionNo, v.TransactionDate, v.TransactionType,
           v.TransactionTypeLabel, v.WarehouseID, v.WarehouseName,
           v.ItemID, v.ItemCode, v.ItemName, v.CategoryName, v.BrandName,
           v.UOMName, v.InQty, v.OutQty, v.RunningBalance,
           v.UnitCost, v.ReferenceType, v.ReferenceNo, v.Remarks
    FROM VWStockLedger v
    WHERE v.TransactionDate BETWEEN @FromDate AND @ToDate
      AND (@WarehouseID = 0 OR v.WarehouseID = @WarehouseID)
      AND (@ItemID = 0 OR v.ItemID = @ItemID)
      AND (@TransactionType = 'ALL' OR v.TransactionType = @TransactionType)
    ORDER BY v.ItemName ASC, v.TransactionDate ASC, v.ID ASC;
END
```

The SP calls `VWStockLedger` — RunningBalance is precomputed in the view across ALL history, not just the filtered window. This gives the correct running balance as-at any point in time.

### 5. Data Access Pattern in ASPX (ADO.NET)

```csharp
private DataTable RunSP(int whID, int itemID, string txType, DateTime from, DateTime to)
{
    var dt = new DataTable();
    using (var conn = new SqlConnection(ConnStr()))
    using (var cmd  = new SqlCommand("sp_InventoryStockLedger", conn))
    {
        cmd.CommandType    = CommandType.StoredProcedure;
        cmd.CommandTimeout = 60;
        cmd.Parameters.AddWithValue("@WarehouseID",     whID);
        cmd.Parameters.AddWithValue("@ItemID",          itemID);
        cmd.Parameters.AddWithValue("@TransactionType", txType ?? "ALL");
        cmd.Parameters.AddWithValue("@FromDate",        from.Date);
        cmd.Parameters.AddWithValue("@ToDate",          to.Date);
        conn.Open();
        new SqlDataAdapter(cmd).Fill(dt);
    }
    return dt;
}
```

### Step 1: Database — Stored Procedure

Create `sp_CurrentStockReport` in a new migration file:
`d:\Gunma\FWG-Malaysia-New\Database\30.CurrentStockReport_Migration.sql`

```sql
-- The SP can simply call the existing view logic or query directly from StockLedger
-- Option A: Use a new view VWCurrentStock (matches StockBalanceSummaryDto)
-- Option B: Direct query — no view needed since data is simple aggregation

CREATE PROCEDURE sp_CurrentStockReport
    @WarehouseID INT = 0,
    @ItemID      INT = 0
AS BEGIN
    SET NOCOUNT ON;
    SELECT
        wh.Name                     AS WarehouseName,
        im.Code                     AS ItemCode,
        im.Name                     AS ItemName,
        ic.Name                     AS CategoryName,
        bm.Name                     AS BrandName,
        um.Name                     AS UOMName,
        SUM(sl.InQty - sl.OutQty)   AS CurrentStock,
        im.ReorderLevel,
        (SELECT TOP 1 sl2.UnitCost
         FROM StockLedger sl2
         WHERE sl2.WarehouseID = sl.WarehouseID AND sl2.ItemID = sl.ItemID
           AND sl2.UnitCost IS NOT NULL
         ORDER BY sl2.TransactionDate DESC, sl2.ID DESC) AS LastUnitCost
    FROM StockLedger sl
        INNER JOIN WarehouseMaster wh ON sl.WarehouseID = wh.ID
        INNER JOIN ItemMaster im      ON sl.ItemID = im.ID
        LEFT  JOIN InventoryCategory ic ON im.CategoryID = ic.ID
        LEFT  JOIN BrandMaster bm       ON im.BrandID = bm.ID
        LEFT  JOIN UOMMaster um         ON im.UOMID = um.ID
    WHERE (@WarehouseID = 0 OR sl.WarehouseID = @WarehouseID)
      AND (@ItemID = 0 OR sl.ItemID = @ItemID)
    GROUP BY sl.WarehouseID, sl.ItemID,
             wh.Name, im.Code, im.Name, ic.Name, bm.Name, um.Name, im.ReorderLevel
    ORDER BY wh.Name ASC, im.Name ASC;
END
```

    params.set('format',      'excel');

}

### ⚠️ Points to Note

1. **ASPX deploy location matters**: The ASPX files are in `UatReports-new\UatReports\Inventory\`, NOT in `OBMSAPP-API`. The IIS server at `localhost:8080` (dev) or `124.217.236.37:8229` (prod) serves from `UatReports-new\UatReports\`.

2. **No code-behind file**: `StockLedgerReport.aspx` has NO `.aspx.cs` file — all logic is inline `<script runat="server">`. Follow this pattern for `CurrentStockReport.aspx`. (BranchStockLedgerReport has a `.cs` file but that's a Crystal Reports pattern — ignore it.)

3. **AppSettings lookup**: The ASPX reads company details (CompanyName, Address1, etc.) from `web.config` `<appSettings>`, not from the database. Make sure the IIS-deployed `web.config` has these keys.

4. **ScreenList entry is required**: Access rights check uses `getUserAccessRights(user, 'Current Stock Report')`. If the ScreenList row doesn't exist, all users except superadmin will see "Access Denied". Always run the migration SQL before deploying.

5. **Reorder Level highlight**: The current `StockLedgerReport` doesn't show low-stock indicators. For the Current Stock Report, consider making rows with `BelowReorderLevel=true` visually distinct (e.g. amber background `#fff3cd`). The `StockBalanceSummaryDto.BelowReorderLevel` boolean is already computed.

6. **SP vs. direct query decision**: You can either:
   - Write a new SP (`sp_CurrentStockReport`) — cleaner, easier to debug in SSMS
   - Call the existing `GetStockBalanceSummary` API from Angular and generate PDF on the client — not the pattern used here
   - Call `GetStockBalanceSummary` API from ASPX via `HttpClient` — over-engineered
   
   **Recommendation**: Write `sp_CurrentStockReport` — it keeps the ASPX self-contained and consistent with `StockLedgerReport.aspx`.

7. **No date range filter**: Current Stock is as-of-NOW. If the business later needs "Current Stock as of a specific date", the SP would need to add a `@AsOfDate` parameter filtering the StockLedger entries by `TransactionDate <= @AsOfDate`.
