Key Design Principles
  • ✓ Stock Ledger is the single source of truth — balance = SUM(InQty) - SUM(OutQty) per item per warehouse
  • ✓ No stored procedures for writes — InventoryRepository uses pure EF Core LINQ with transactions
  • ✓ Reports use separate server — ASPX calls SPs directly, not the JSON API
  • ✓ Finance integration — only GRN creates CreditorInvoice (InvoiceType='G')
  • ✓ Screen-level RBAC — getUserAccessRights(userName, screenName) per screen

Approval Workflow Framework

Shared Infrastructure
Document Types
Document TypeApproval Required?
Purchase RequisitionRequired
Purchase OrderRequired
Branch Stock RequestRequired
Stock AdjustmentOptional
Stock TransferOptional
Damage / LossOptional
Asset DisposalOptional
Configurable: Admin can toggle ApprovalRequired per document type via Approval Setup screen. Self-approval blocked unless SuperAdmin.
How It Works
  • ✓ ApprovalConfiguration — master on/off switch per document type
  • ✓ ApprovalRouting — maps (DocumentType + RequesterUser) → ApproverUser
  • ✓ If no routing configured → document auto-approves on Submit
  • ✓ ApprovalHistory — immutable audit trail (never deleted/updated)
  • ✓ AppNotification — real-time push via SignalR to approver
  • ✓ PRProcessingTask — Purchase dept inbox (atomic claim via conditional UPDATE)
  • ✓ JWT identity used for all actions — client-supplied usernames ignored
  • ✓ SuperAdmin (IsAdmin=2) can self-approve any document

Key Relationships
Procurement chain:
PR → PO (PRID nullable) → GRN (POID) → PurchaseReturn (GRNID)
Item dependencies:
ItemMaster → Category (req), Brand (opt), UOM (opt), Warehouse (opt)
Stock Ledger is written by:
Opening, GRN, Issue, IssueReturn, Transfer (paired), Adjustment (on Approve), DamageLoss, PurchaseReturn
Finance bridge:
SaveGRN → CreditorInvoice (InvoiceType='G')
DeleteGRN → reverses CreditorInvoice (blocked if payment)
VWStockLedger view:
StockLedger + Warehouse + Item + Category + Brand + UOM
RunningBalance = SQL window function
All migrations are idempotent (IF NOT EXISTS guards). 92 SQL files numbered 01–51. Run once each in order.

  • ✗ Purchase Return — no delete/reversal path
  • ✗ Stock Issue Return — no edit or delete

  • ✗ No SST/Tax — zero tax logic in inventory (dormant TAX constant)
  • ⚠ Stock Adjustment — single item per document only
  • ⚠ Server deploy — some report SPs + BouncyCastle DLL pending

  • ✓ Add Delete for Purchase Return & Issue Return
  • ✓ Enable UI edit for Stock Issue / Transfer / Damage-Loss
  • ✓ Add dependency check APIs (mirrors GRN pattern)
